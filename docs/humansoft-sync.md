# ส่งรายการจาก FUQ HONO Web เข้า HumanSoft

ใช้กับพนักงานของ HONO บริษัท PSD ที่ผู้ดูแลผูกกับรหัสพนักงาน HumanSoft ของ NWL และบริษัทอนุญาตให้รับเวลาจาก HONO เป็นรายการนำเข้า รหัสผ่านแอปพนักงานใช้สำหรับล็อกอินของบุคคล ส่วนการนำเข้าใช้สิทธิ์องค์กร ตั้งค่าที่ backend เท่านั้น

เมื่อพนักงานลงเวลาผ่านหน้าเว็บ ระบบตรวจใบหน้าและส่ง HONO ตามเดิม สำหรับพนักงานที่ผูกบัญชี ฟังก์ชันจองรายการก่อนส่ง HONO และเริ่มส่งต่อหลัง HONO ยืนยัน โดยนำเวลาเข้า/ออกจากบรรทัดใหม่ในประวัติของพนักงาน รหัสพนักงานปลายทางมาจาก mapping บนเซิร์ฟเวอร์

| เหตุการณ์ | พฤติกรรม |
| --- | --- |
| ปุ่มเข้า / ออก | ส่งรายการ `ADD` หนึ่งรายการด้วย `time_attendance_type` เท่ากับ `IN` หรือ `OUT` |
| HONO มีเพียงเวลาแสดงถึงนาที | ส่งวินาทีเป็น `00` วันที่ใช้ตามประวัติ HONO ในเวลาไทย |
| HONO ปฏิเสธ หรือผลการเขียน HONO ยังไม่ทราบ | ไม่มีคำขอนำเข้า HumanSoft |
| ประวัติ HONO ยังไม่อัปเดต หรือพบเวลาใหม่ที่จับคู่ไม่ได้แน่ชัด | เก็บรายการรอประวัติ หลังส่งเว็บรีเฟรชประวัติให้อัตโนมัติ เมื่อเปิดประวัติวันนั้นอีกครั้งจะตรวจต่อ |
| HumanSoft มีรายการของพนักงาน เวลา และทิศทางนั้นแล้ว | แสดงว่าพบในประวัติ โดยไม่ส่งซ้ำ |
| HumanSoft รับคำขอเข้าคิว | แสดงเข้าคิว ตรวจสถานะด้วยการอ่านประวัติ |
| เขียนแล้วหมดเวลา หรือกระบวนการหยุดระหว่างส่ง | ตรวจจากประวัติปลายทางเมื่อเปิดประวัติครั้งถัดไป การลองอ่านซ้ำไม่ส่ง POST ซ้ำ |
| HumanSoft ปฏิเสธรายการ | แสดงผลปฏิเสธ ผู้ดูแลตรวจรายการต้นทางและปลายทางก่อนแก้ไข |
| จองรายการในฐานข้อมูลไม่ได้ขณะเปิดใช้กับบัญชีนี้ | แจ้งข้อผิดพลาดก่อนส่ง HONO เพื่อป้องกันการเขียนซ้ำ |
| กระบวนการหยุดระหว่าง HONO รับรายการกับการเก็บผล | เก็บสถานะ reserved ให้ผู้ดูแลเทียบประวัติทั้งสองระบบก่อนดำเนินการต่อ |

**ข้อจำกัดการทำงานอัตโนมัติ** กรณีส่งต่อได้ในคำขอแรก งานดำเนินการบนเซิร์ฟเวอร์ กรณีต้องรอประวัติหรือปลายทางกลับมาออนไลน์ ระบบตรวจต่อจากการโหลดประวัติ ยังไม่มี worker ทำรายการระหว่างที่เว็บปิด หากประวัติในวันเดียวเกิน 100 รายการ ระบบพักการนำเข้าแทนการตัดสินจากข้อมูลหน้าเดียว

**การตั้งค่าสำหรับทดสอบ** สร้างตัวแปรใน Vercel Preview ของ branch นี้ ใช้บัญชีทดสอบที่มีอยู่จริงทั้งสองระบบ เก็บ UAT และ production แยกกัน

| ตัวแปร | ค่าที่ต้องเตรียม |
| --- | --- |
| `HUMANSOFT_IMPORT_MODE` | `uat` เรียก /uat, `production` ใช้ได้เฉพาะ deployment ประเภท production ค่าเริ่มต้นปิด |
| `HUMANSOFT_IMPORT_KEY` | Subscription key ที่ NWL อนุญาตให้ใช้สำหรับนำเข้าและอ่านประวัติ attendance ใน environment นั้น |
| `HUMANSOFT_EMPLOYEE_MAP` | JSON object ตัวอย่างรูปแบบ `{"HONO_TEST_EMP":"HS_TEST_EMP"}` รหัสปลายทางไม่ซ้ำ บัญชีนอก mapping ใช้ HONO ตามเดิม |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | Upstash Redis สำหรับเก็บสถานะและจองรายการข้าม Vercel instances รองรับชื่อตัวแปร `KV_REST_API_URL`, `KV_REST_API_TOKEN` ด้วย |

ฐานข้อมูลเก็บสถานะ เวลา และทิศทางเป็นเวลา 45 วันภายใต้คีย์ที่แยก environment และ hash บัญชี ไม่เก็บภาพ รหัสผ่าน หรือ token ของพนักงาน การตรวจปลายทางใช้รายการจากบัญชีและวันที่เดียวกัน บทบาทแอปพนักงานและข้อกำหนดของบริษัทสำหรับการยืนยันตัวตนยังคงใช้เมื่อพนักงานลงเวลาใน HumanSoft โดยตรง

**UAT** ใช้ปุ่มเข้าและปุ่มออกตามรอบทดสอบจริง เทียบรหัสพนักงาน วันที่ เวลา ทิศทาง และเลขรายการจากประวัติ HumanSoft ผลรับเข้าคิวต้องผ่านการเทียบประวัติอีกครั้งก่อนถือว่าส่งถึงแล้ว การทดสอบอัตโนมัติใน repository ใช้ชุดข้อมูลสังเคราะห์

เอกสารผู้ให้บริการ [Import Time Attendance](https://docs.humansoft.co.th/docs/api-reference/time-attendance/import) และ [Search Time Attendance](https://docs.humansoft.co.th/docs/api-reference/salary/attendance/search-time-attendance)
